1. If You Only Have 2 Hours to Study

Focus on understanding the core concepts and the main techniques covered, especially those marked or in the detailed sections. Prioritize:
  1. R Basics (Week 1): Understand how to create and manipulate vectors, data frames. Know basic subsetting ([], $) and the purpose of dplyr (group_by, summarise, mutate).
  2. Conjoint Analysis (Week 2): Understand the concept (breaking products into attributes/levels to find preferences), how to interpret part-worths and importance scores. Know its applications (pricing, market share).
  3. STP & Clustering (Week 3): Understand Segmentation, Targeting, Positioning basics. Know the difference between segmentation bases (esp. Behavioral). Understand the concept of clustering (grouping similar customers) and how K-Means/Hierarchical work at a high level. Understand how to profile segments.
  4. Pricing Concepts (Weeks 4 & 5): Understand Price Elasticity concept. Know the purpose of different pricing strategies (Skimming, Block Pricing, Bundling, Discrimination) and the basic idea of optimizing price for profit using demand curves (even if you don't memorize Excel steps).
  5. Marketing Mix & Adstock (Week 6): Understand the 4 Ps. Know the Adstock concept (advertising effect decays over time, lambda). Understand the goal of Marketing Mix Models (allocating budget).
  6. Recommender Systems (Week 7): Understand the difference between Collaborative Filtering (User-based vs Item-based) and Content-Based filtering at a high level. Know the core idea (recommending based on similar users/items or item features).
  7. RFM & Market Basket Analysis (Week 8): Understand RFM (Recency, Frequency, Monetary) and how scores are calculated/interpreted for customer value . Understand Market Basket Analysis goal (finding co-purchased items) and the meaning of Support, Confidence, Lift .
  8. Churn & CLV (Week 9): Understand the concept of Customer Churn. Understand Customer Lifetime Value (CLV) conceptually (profit over customer lifespan, including acquisition cost, retention). Know the purpose of Survival Analysis (predicting time-to-event like churn).
  9. Text Mining Basics (Weeks 10 & 11): Understand the need for text pre-processing (cleaning, stopwords). Know what a DTM is. Understand the concept of Sentiment Analysis (positive/negative) and how Naive Bayes or Lexicons are used. Understand TF-IDF concept (word importance).
  10. Social Network Analysis Basics (Week 12): Understand Nodes and Paths. Know the concept of Centrality (identifying important people).

2. Brief Course Overview

2.1 Course Description

This course, Marketing Analytics, assumes prior knowledge of Marketing Management and basic Business Analytics tools (including R programming). It focuses on combining these concepts to solve real-world marketing problems through quantitative analysis and storytelling. The course emphasizes identifying sequences of analytical approaches to tackle complex marketing challenges, moving from understanding customer needs to optimizing marketing strategies and analyzing specific areas like retail, services, and online content.

2.2 Learning Objectives

Upon completion of this course, you should be able to:
  • Deconstruct marketing problems into smaller, answerable analytical questions.
  • Identify suitable analytical tools and datasets for each question.
  • Apply various quantitative tools (statistical, machine learning) effectively and select the best approach.
  • Translate analytical results into compelling marketing narratives and insights.
  • Execute a marketing analytics project from problem definition to solution proposal.

2.3 Prerequisites

  • Marketing Management: Basic understanding of core marketing concepts (4Ps, STP, etc.).
  • Basic Business Analytics: Familiarity with introductory statistics and analytics concepts.
  • Basic R Programming: Foundational knowledge of R programming is expected (as covered in Week 1).

  • 1.3 Detailed Explanation: R Basics - Vectors
    • Concept: A vector is the most basic R object, like a single column, holding elements of the same data type.
    • Assignment: Use <- (preferred) or = to assign values to variables (vectors).
      # Assign single numeric value
a <- 0
b <- 5
# Print value
a # Output: [1] 0
# Arithmetic
a + b # Output: [1] 5
    • Creating Sequences:
      • Colon operator : for integer sequences: a <- 1:10 (creates vector 1, 2, ..., 10)
      • seq() function for more control: a <- seq(from=1, to=30, by=2) (creates 1, 3, 5, ..., 29)
    • Combining Elements: Use c() (combine/concatenate) function.
      # Numeric vector
b <- c(2, 5, 6, 8, 9)
# Character vector
m <- c("apple", "banana", "apple")
    • Repeating Elements: Use rep() function.
      # Repeat 2 twenty times
b <- rep(2, 20)
# Repeat "png" 5 times, then "hul" 10 times, etc.
m <- c(rep("png", 5), rep("hul", 10), rep("marico", 5))
    • Vector Info:
      • length(vector_name): Number of elements.
      • class(vector_name): Data type ("numeric", "integer", "character", "factor", "logical").
    • Data Types:
      • Numeric/Integer: Numbers.
      • Character: Text strings (always in quotes). Math operations don't work directly.
      • Factor: Special type for categorical data. Stores categories efficiently using internal numeric codes mapped to text "levels". Useful for representing groups like brands, gender, regions.
        m <- c(rep("png", 5), rep("hul", 10), rep("marico", 5))
class(m) # "character"
mm <- as.factor(m) # Convert to factor
class(mm) # "factor"
print(mm) # Shows levels: hul marico png
levels(mm) # Returns the unique levels
as.numeric(mm) # Shows internal numeric codes (1, 2, 3 based on alpha order)
# Changing levels changes all occurrences:
levels(mm)[2] <- "Nestle" # Replaces "marico" with "Nestle"
      • Logical: TRUE or FALSE. Often result from comparisons.
    • Getting Help: Use ?function_name or help(function_name) to view documentation in the Help pane. Use online search ("how to do X in R") for unknown functions.
  • 1.4 Detailed Explanation: R Basics - Data Frames and Matrices
    • Matrix: A 2-dimensional structure (rows, columns) where all elements must be the same data type. If different types are combined, R converts them to the most flexible type (usually character).
      • Creating Matrices:
        • cbind(vec1, vec2): Column-bind vectors (must have same length). Result has columns = number of vectors, rows = length of vectors.
        • rbind(vec1, vec2): Row-bind vectors. Result has rows = number of vectors, columns = length of vectors.
        • matrix(data_vector, nrow=n, byrow=FALSE): Fills matrix column-wise (default) or row-wise (byrow=TRUE).
        # Example
a <- 1:10
b <- seq(2, 10, length.out = 10)
c_char <- rep(c("Sachin", "Saurav"), each = 5)
matrix1 <- cbind(a, b, c_char) # Result is character matrix
# View structure
str(matrix1)
# View content
View(matrix1)
matrix3 <- matrix(1:9, nrow=3) # Fills column-wise
    • Data Frame: A 2-dimensional structure (rows=observations, columns=variables) like a spreadsheet, where columns can have different data types. This is the most common structure for datasets in R.
      • Creating Data Frames: Use data.frame().
        # Create vectors first
company <- c("png", "png", "png", "hul", "hul", "hul")
fy <- c(1999, 2000, 2001, 1999, 2000, 2001)
revenue <- c(11234, 14567, 15698, 12345, 14567, 16789)
# Create data frame
Data <- data.frame(company, fy, revenue) # Column names match vector names
Data2 <- data.frame(Ticker=company, Year=fy, Sales=revenue) # Assign custom names
# View structure
str(Data) # Shows 'obs. of variables'
    • Accessing Columns: Use the $ operator with data frames.
      Data$revenue # Returns the revenue vector
mean(Data$revenue) # Calculate mean of the revenue column
  • 1.5 Detailed Explanation: Subsetting Data
    • Concept: Selecting specific elements, rows, or columns from vectors, matrices, or data frames using square brackets [].
    • Vector Subsetting: vector[index]
      a <- seq(1, 15, by=2) # 1 3 5 7 9 11 13 15
a[3] # Select 3rd element (5)
a[c(1, 4, 5)] # Select 1st, 4th, 5th elements (1, 7, 9)
a[2:5] # Select elements from 2nd to 5th (3, 5, 7, 9)

    • Goal: Understand how customers value different attributes (features) and specific levels (values) of those attributes when choosing a product/service. Helps understand trade-offs.
    • Consumer Surplus: Customers aim to maximize Value - Price. Conjoint helps understand the 'Value' component.
    • Company Dilemma: Balancing increasing value (increases cost) vs. decreasing price (decreases margin) to maximize profit. Conjoint informs this by quantifying value.
    • Limitations of Traditional Research:
      • Qualitative (FGDs, Reviews): Tells what people talk about, not precise trade-offs or valuations.
      • Regression on existing data: Cannot evaluate hypothetical products.
      • Direct Questioning: Vague answers ("more RAM", "latest OS"), doesn't reveal trade-offs.
      • Importance Rating/Ranking: Gives relative importance but not the value of specific levels or how they trade off against price.
    • Conjoint Solution: Overcomes these limitations by presenting realistic product profiles and analyzing preferences for combinations.

    • Step 1: Decide Product/Service: Define the scope.
    • Step 2: Decide Attributes & Levels:

Ensures efficient data collection while allowing estimation of main effects. (Creating these requires specific methods/software - mentioned but not detailed).
      • Ensure combinations are meaningful (e.g., avoid "Apple Brand + Windows OS").
    • Step 4: Data Collection: Present profiles to respondents and collect preferences.
      • Ranking-based: Rank profiles from most to least preferred.

  • 2.8 Detailed Explanation: Calculating Part-Worths and Importance Scores (L9)
    • Part-Worth Utility: The value or preference associated with a specific level of an attribute. The regression coefficients are relative part-worths.
    • Centering Part-Worths: To compare levels within and across attributes fairly, center the utilities so the average utility for each attribute's levels is zero.
      1. Get raw coefficients (including 0 for reference level).
      2. Calculate average coefficient per attribute.
      3. Subtract attribute average from each level's raw coefficient.
    • Attribute Importance: Measures the overall impact of an attribute on preference. Calculated as the range of centered part-worth utilities for that attribute (Max Utility - Min Utility).
      1. Calculate Range for each attribute.
      2. Calculate Total Range across all attributes.
      3. Relative Importance (%) = (Attribute Range / Total Range) * 100.
      • Example Result: Capacity (37%) > Fuel (35%) > Price (28%). This tells which attribute drives preference differences the most.

    • Concept: Models the probability of choosing option j from a set k based on the utility of j relative to the utilities of all other options m in the set k.
      • P(Choose j | Set k) = exp(Utility_j) / Sum(exp(Utility_m) for all m in k)
      • Utility_j = B0 + B1*Attribute1_j + B2*Attribute2_j + ... (Linear utility function assumed)
    • R Implementation (survival::clogit()): [EXAM-FOCUS if covered in detail]
      • Requires data in long format (one row per option within a choice set).
      • Special formula: clogit(c(choice_col, choice_set_id_col) ~ attribute1 + attribute2 + ... + strata(choice_set_id_col), data = data)
      • choice_col is 1 if chosen, 0 otherwise. choice_set_id_col identifies options belonging to the same choice set. strata() conditions the analysis within each set.
    • Interpretation: Coefficients (coef) represent change in utility for a change in attribute level. exp(coef) gives the odds ratio (change in odds of choosing an option with that attribute level vs. base level). Check significance (p-value).
    • Interaction Effects: Can add interaction terms (e.g., distance*Gender) to see how preferences vary by demographics. Interpret interaction coefficients as the additional effect compared to the main effect.

  • 3.2 Detailed Explanation: Segmentation, Targeting, Positioning (STP) - Why & What (L13)
    • What: A strategic marketing process.
      • Segmentation: Dividing a broad market into distinct subsets (segments) of consumers who have common needs or characteristics. Goal: Groups are similar within, different between.
      • Targeting: Selecting one or more segments to enter, based on attractiveness and company fit.
      • Positioning: Designing the company's offering and image to occupy a distinctive place in the minds of the target market relative to competitors.
    • Why:
      • Customers have diverse preferences (heterogeneity).
      • A "one-size-fits-all" or "middle path" approach often fails to satisfy anyone well (e.g., lukewarm tea example).
      • Companies have limited resources and cannot cater effectively to everyone.
      • STP allows companies to focus efforts on segments they can serve best, leading to greater efficiency and effectiveness.
  • 3.3 Detailed Explanation: Bases for Segmentation (Geo, Demo, Psycho, Behavioral - L13, L14)
    • Geographic: Dividing by location (nations, regions, cities, climate, density). Assumes people in the same area share similar needs/wants (e.g., food preferences, climate-based clothing).
    • Demographic: Dividing by objective characteristics like age, gender, income, family size, life cycle stage, occupation, education, religion, race, generation (e.g., Millennials, Gen Z), social class. Most common base due to ease of measurement. (e.g., Indian wedding market segmentation).
    • Psychographic: Dividing based on lifestyle, personality traits, values, attitudes, interests, opinions (AIOs). Explains why people buy. Requires deeper research. (e.g., music listener segments: Fanatics, Enthusiasts, Casuals; VALS framework).
    • Behavioral: Dividing based on knowledge of, attitude towards, use of, or response to a product. Considered highly relevant for predicting future behavior.
      • Variables: Occasions (regular, special), Benefits Sought (quality, service, economy), User Status (non-user, ex-user, potential, first-time, regular), Usage Rate (light, medium, heavy), Loyalty Status (hard-core, split, shifting, switchers), Buyer-Readiness Stage (aware, informed, interested, desire, intention), Attitude (enthusiastic, positive, indifferent, negative, hostile). (e.g., Pregnancy test kit segments).
  • 3.4 Detailed Explanation: Emphasis on Behavioral Segmentation & Profiling (L13, L14)
    • Why Behavioral First? In marketing analytics with rich data (scanner data, web behavior), behavioral segmentation is often preferred because:
      • It's based on actual actions, not stated preferences or demographics which may not correlate perfectly with behavior.
      • It's closest to the desired outcome (purchase, engagement).
      • It's harder for customers to manipulate or misrepresent.
    • Process:
      1. Segment using Behavior: Use behavioral variables (e.g., purchase history, RFM scores, usage patterns) as input for clustering algorithms to create segments with distinct behavioral profiles.
      2. Profile using Demographics/Psychographics: After creating behavioral segments, use descriptive variables (demographics, psychographics, geographics) to understand who is in each segment. Calculate average characteristics (age, income, location, lifestyle indicators) for each segment. This helps in understanding the segments and designing targeted marketing communications.
      • Example: Segment 1 buys frequently, high value (Behavior) -> Profile: Found to be older males, high income (Demographics).
  • 3.5 Detailed Explanation: Effective Segmentation Criteria (L14)
    • Measurable: Size, purchasing power, characteristics can be measured.
    • Substantial: Segments are large and profitable enough to serve.
    • Accessible: Segments can be effectively reached and served (via distribution, communication).
    • Differentiable: Segments respond differently to different marketing mix elements. Homogeneous within, heterogeneous between.
    • Actionable: Effective programs can be designed for attracting and serving the segments.
    • (Stable): Segments remain relatively consistent over time (mentioned in L14).
  • 3.6 Detailed Explanation: Targeting Strategies (L14)
    • Evaluating Segments: Assess segments based on:
      • Segment Attractiveness: Size, growth rate, profitability, scale economies, low risk.
      • Company Objectives & Resources (Competitive Strength): How well the segment fits the company's goals, resources, capabilities, and competitive advantages.
    • Selection Matrix: Plot segments on an Attractiveness vs. Capability matrix to guide selection. Target segments in high-high, high-medium, or medium-high quadrants based on strategy. Avoid low-low.
    • Targeting Approaches:
      • Single-segment concentration.
      • Selective specialization.
      • Product specialization.
      • Market specialization.
      • Full market coverage (undifferentiated or differentiated marketing).
  • 3.7 Detailed Explanation: Positioning (PODs, POPs - L14)
    • Concept: The act of designing the company's offering and image to occupy a meaningful and distinct competitive position in the target customer's mind.
    • Goal: Achieve top-of-mind awareness ("Share of Mind") and preference ("Share of Heart") leading to market share.
    • Key Elements:
      • Points of Difference (POD): Attributes/benefits consumers strongly associate with a brand, evaluate positively, and believe they cannot find to the same extent with competitors. Must be Desirable, Deliverable, Differentiating. (e.g., FedEx reliability, Apple design).
      • Points of Parity (POP): Attributes/benefits not necessarily unique but essential for legitimacy within a category or to negate competitor PODs. Needed to be "in the game." (e.g., all banks offer basic accounts, YiPPee! needs noodle-like qualities to compete with Maggi).
    • Positioning Strategy: Establish necessary POPs to be considered, then create strong, unique PODs to differentiate. (e.g., Tanishq ad establishing contemporary POPs and home-try-on POD).

  • 3.9 Detailed Explanation: Cluster Analysis Methods (Hierarchical, K-Means, Ward's - L15)
    • Goal: Group data points (customers) such that points within a cluster are similar (close) and points in different clusters are dissimilar (far).
    • Distance Metric: Need a way to measure distance/similarity between points (based on the segmentation variables). Euclidean Distance is common for numeric data: sqrt(sum((xi - xj)^2)).
    • Hierarchical Clustering: Builds a nested hierarchy of clusters.
      • Agglomerative (Bottom-up): Starts with each point as a cluster, merges closest clusters iteratively until one cluster remains.
      • Divisive (Top-down): Starts with one cluster, splits recursively until points are separate.
      • Linkage Methods (for merging clusters): Single (min distance), Complete (max distance), Average (avg distance), Centroid (distance between means), Ward's Method (minimizes increase in within-cluster variance - aims for compact, spherical clusters, sensitive to outliers). [Ward's is commonly used].
      • Output: Dendrogram (tree diagram showing merges). Cut the dendrogram at a desired height or number of clusters.
    • K-Means Clustering: Partitions data into a pre-specified number (K) of clusters.
      1. Choose K.
      2. Initialize K cluster centroids (means) randomly or strategically.
      3. Assign each data point to the nearest centroid (using Euclidean distance).
      4. Recalculate centroids as the mean of points assigned to each cluster.
      5. Repeat steps 3-4 until assignments stabilize (convergence).
      • Pros: Efficient for large datasets.
      • Cons: Need to specify K beforehand; sensitive to initial centroid placement (run multiple times with nstart in R); assumes spherical clusters.
    • Choosing K (Number of Clusters):
      • Dendrogram (Hierarchical): Look for large vertical gaps indicating distinct merge points.
      • Elbow Method (K-Means/Ward's): Plot Within-Cluster Sum of Squares (WSS) against different values of K. Look for an "elbow" point where adding more clusters provides diminishing returns (WSS decrease flattens). WSS measures cluster compactness (lower is better).

  • 4.2 Detailed Explanation: Pricing Optimization Basics (Linear/Non-Linear Demand - L18)
    • Concept: Finding the price that maximizes profit, given a demand function and cost structure.
    • Demand Function: Relationship between Price (P) and Demand (D). Often D = a - bP (linear) or polynomial/other non-linear forms. Can be estimated from historical data using Excel scatter plot trendlines (Insert -> Scatter, Right-click -> Add Trendline, Display Equation).
    • Profit Function: Profit = (Price - Unit Cost) * Demand. Substitute the demand function to express profit in terms of Price.
    • Excel Solver: Optimization tool (Data -> Solver).
      • Set Objective: Cell containing the Profit calculation.
      • To: Max.
      • By Changing Variable Cells: Cell containing the Price.
      • Constraints: e.g., Price >= 0.
      • Solving Method: GRG Nonlinear (handles non-linear profit functions).
    • Example (Linear Demand, Cost=0): D = 2000 - 10P. Solver finds optimal P = 100.
    • Example (Non-Linear Demand, Fixed Cost): D = -44P^2 + 136P - 45, Unit Cost = 0.6. Solver finds optimal P ≈ 1.97.
  • 4.3 Detailed Explanation: Two-Part Pricing (Razor/Blade Example - L18)
    • Concept: Profit comes from a primary "capital" item (e.g., razor, printer) sold at low/no margin and high-margin "consumables" (blades, ink). Optimize the price of the capital item to maximize total profit.
    • Model:
      • Demand for Capital Item = f(Price of Capital Item).
      • Profit from Capital Item = Demand * (Price - Unit Cost)_Capital.
      • Profit from Consumables = Demand_Capital * (Units Consumed per Capital Item) * (Profit per Consumable Unit).
      • Total Profit = Profit_Capital + Profit_Consumables.
    • Excel Solver: Maximize Total Profit by changing the Price of the Capital Item.
    • Example (Razor/Blade): Razor Demand = 32 - 2 * Razor Price, Razor Cost = 8, Blades/Razor = 15, Profit/Blade = 1. Solver finds optimal Razor Price ≈ 4.5 (below cost), maximizing total profit through blade sales.
  • 4.4 Detailed Explanation: Pricing with Variable Unit Cost (L18)
    • Concept: Unit cost is not fixed but depends on production volume (Demand), often decreasing with higher demand (economies of scale).
    • Model:
      • Demand = f(Price)
      • Unit Cost = g(Demand)
      • Profit = Demand * (Price - Unit Cost) = Demand * (Price - g(Demand)) = f(Price) * (Price - g(f(Price))).
    • Excel Implementation:
      1. Estimate Demand = f(Price) using trendline.
      2. Estimate Unit Cost = g(Demand) using trendline.
      3. In separate cells: Calculate Demand based on Price (using f(P)). Calculate Unit Cost based on calculated Demand (using g(D)). Calculate Profit.
    • Excel Solver: Maximize Profit by changing Price.
    • Example: Solver finds optimal Price ≈ 1.22, considering the feedback loop between price, demand, and unit cost.
  • 4.5 Detailed Explanation: Bundle Pricing Concept (Negative Correlation, WTP - L19)
    • Concept: Selling two or more products together as a package, often at a discount compared to buying items separately.
    • Why Bundle? Particularly effective when customer Willingness to Pay (WTP) for the individual items is negatively correlated (customers valuing item A highly tend to value item B less, and vice-versa). Bundling can capture more total WTP across diverse customers.
    • WTP for Bundle: Often assumed to be the sum of WTPs for individual components.
    • Goal: Set bundle price (and potentially individual prices in mixed bundling) to maximize total profit/revenue.
  • 4.6 Detailed Explanation: Bundle Pricing Examples & Profit Calculation (L19)
    • Example 1 (2 Customers, 2 Products, No Costs):
      • C1: WTP(CPU)=900, WTP(Mon)=400 -> WTP(Bundle)=1300
      • C2: WTP(CPU)=400, WTP(Mon)=900 -> WTP(Bundle)=1300
      • Individual Pricing Max Revenue: CPU at $900 (buys C1), Monitor at $900 (buys C2) -> Total = $1800.
      • Bundle Pricing Max Revenue: Bundle at $1300 (buys C1 & C2) -> Total = $2600. Bundling is better.
    • Example 2 (4 Customers, 2 Products, With Costs):
      • Costs: CPU=1200, Mon=500, Bundle=1700. WTPs vary but Bundle WTP is 2000 for all.
      • Individual Pricing Max Profit: CPU at $1400/$1600 (Profit $400), Monitor at $800 (Profit $600) -> Total Profit = $1000.
      • Bundle Pricing Max Profit: Bundle at $2000 (Profit $300/unit * 4 units) -> Total Profit = $1200. Bundling is better.
    • Types:
      • Pure Bundling: Only bundle offered.
      • Mixed Bundling: Both bundle and individual items offered. Choice depends on maximizing overall profit.
  • 4.7 Detailed Explanation: Time Series Decomposition (Trend, Seasonality, Error - L20)
    • Concept: Breaking down a time series (like Sales over time) into its underlying components to understand patterns and make forecasts.
    • Additive Model: Xt = Tt + St + Et (Level changes, pattern constant)
    • Multiplicative Model: Xt = Tt * St * Et (Pattern magnitude changes with level)
    • Components:
      • Trend (Tt): Long-term upward or downward movement (e.g., growth due to population).
      • Seasonality (St): Patterns repeating over a fixed period (daily, weekly, monthly, quarterly, annually) (e.g., summer sales spike). Cycles are similar but longer term (> 1 year).
      • Error (Et) / Residual: Random fluctuations or effects of external factors not captured by Tt and St. Ideally has mean 0, no pattern. Can be modeled using other variables: Et = f(Price_t, Ad_t, ...).
  • 4.8 Detailed Explanation: Decomposition Implementation in Excel (SMA, MOD, Solver - L20)
    • Goal: Estimate Tt and St from historical Sales data (Xt).
    • Steps (Excel):
      1. Plot Data: Visualize Xt vs. time to identify potential trend and seasonality period.
      2. Estimate Trend (Tt): Use Simple Moving Average (SMA). Choose a period (e.g., 3 months) to smooth out short-term fluctuations. Calculate average of current, previous, next points. Limitation: Loses data at ends, might retain some seasonality.
      3. De-trend Data: Calculate initial error: Error_SMA = Xt - SMA. This contains St + Et.
      4. Estimate Seasonality (St):
        • Assume seasonality period based on data/plot (e.g., 3 months).
        • Use MOD(TimePeriod, SeasonalityPeriod) to create seasonal indices (0, 1, 2 for period 3).
        • Create a lookup table for seasonal factors (initial guess: 1).
        • Use VLOOKUP based on MOD index to get Predicted_Seasonality for each Xt.
      5. Calculate Final Error (Et): Error_2 = Error_SMA - Predicted_Seasonality.
      6. Optimize Seasonal Factors: Use Excel Solver to minimize RMSE (SQRT(AVERAGE((Error_2)^2))) by changing the seasonal factors in the lookup table.
    • Forecasting:
      • Project Trend (e.g., assume last SMA value continues, or regress SMA vs time).
      • Apply optimized Seasonal Factors based on future time period's MOD index.
      • Forecast_Xt = Forecast_Tt + Forecast_St.
    • Modeling Residual (Et): Use the final Error_2 column as the dependent variable in a regression against Price, Advertising, etc. from the corresponding time periods.
  • 4.9 Detailed Explanation: Bass Diffusion Model (Concept, p & q, S-curve - L21)
    • Concept: Models the adoption/diffusion of new products (often durables/technology) over time. Assumes adoption is driven by Innovators (adopt independently) and Imitators (adopt based on word-of-mouth/seeing others adopt).
    • Variables:
      • f_t: Proportion adopting at time t.
      • F_t: Cumulative proportion adopted up to time t.
      • m: Total market potential (often normalized to 1 or 100%).
      • (1 - F_t): Remaining potential adopters at time t.
    • Core Equation: f_t / (1 - F_t) = p + q * F_t
      • p: Coefficient of Innovation (external influence).
      • q: Coefficient of Imitation (internal influence/word-of-mouth).
    • Shape: Cumulative adoption (F_t) follows an S-curve. Sales rate (f_t) follows a curve rising to a peak then declining.
    • Formulas: (Derived from solving differential equation)
      • F_t = [1 - e^-(p+q)t] / [1 + (q/p) * e^-(p+q)t]
      • f_t = [(p + q)^2 / p] * [e^-(p+q)t] / [1 + (q/p) * e^-(p+q)t]^2 (Check exact form if needed for exam)
      • Time to Peak Sales: t_peak = [ln(q) - ln(p)] / (p + q)
    • Interpretation: High p = fast initial takeoff. High q = strong viral/word-of-mouth effect.
  • 4.10 Detailed Explanation: Bass Model Estimation in Excel (Solver - L21)
    • Goal: Estimate p and q (and potentially m) from historical cumulative sales data.
    • Steps (Excel):
      1. Input Data: Time periods (t), Actual Cumulative Sales (CS_t_actual).
      2. Initial Guesses: Set cells for p, q, m (if estimating).
      3. Calculate Predicted Sales: Use the F_t formula multiplied by m to get CS_t_predicted for each t, using the guessed parameters. Use absolute references ($) for p, q, m.
      4. Calculate Error: Calculate squared error (CS_t_actual - CS_t_predicted)^2 for each t.
      5. Calculate Overall Error: Calculate RMSE or SSE (sum of squared errors).
      6. Excel Solver:
        • Set Objective: Minimize RMSE (or SSE).
        • By Changing Variable Cells: Cells containing p and q (and m if optimizing).
        • Constraints: p >= 0.001, q >= 0.001 (non-negative, avoid division by zero). Optionally m bounds.
        • Solving Method: GRG Nonlinear.
    • Output: Optimized values for p and q that best fit the historical data.
    • Application: Use estimated p and q in the F_t formula to forecast future adoption and time to market saturation. Model the error from the Bass fit against marketing mix variables to see their impact.

  • 5.2 Detailed Explanation: Skimming Pricing (Concept, Excel Solver Example - L22)
    • Concept: Strategy for new products, starting with a high price to capture high WTP customers (early adopters) and gradually lowering the price over time to attract more price-sensitive segments. Aims to maximize total revenue/profit over the product's introduction phase.
    • Model Logic:
      • Track sales period by period.
      • Demand in period t depends on the cumulative potential demand at Price(t) minus the cumulative units already sold in periods 1 to t-1.
      • Unit Sales(t) = (Cumulative Demand at Price(t)) - (Cumulative Units Sold up to t-1)
      • Revenue(t) = Price(t) * Unit Sales(t)
      • Total Revenue = Sum(Revenue(t))
    • Excel Solver Implementation:
      1. Setup columns: Time, Price (Variable), Cumulative Demand (f(Price)), Unit Sales (calculated), Revenue (calculated).
      2. Calculate Total Revenue cell.
      3. Objective: Maximize Total Revenue.
      4. Changing Variables: Prices for all time periods.
      5. Constraints: Prices >= 0, Prices <= Max WTP (or reasonable upper bound). Optional: Integer prices. Implicit constraint: Prices should generally decrease over time, though Solver might find this automatically.
      6. Method: GRG Nonlinear.
    • Result: Solver finds a sequence of decreasing prices maximizing total revenue (e.g., 91, 82, 73... -> Total Revenue 4636).
  • 5.3 Detailed Explanation: Power Block Pricing (Tiered Systems, Excel Solver Example - L23)
    • Concept: Charging different per-unit prices for different consumption blocks (tiers). Common in utilities (electricity, water). Can be increasing block (higher price for higher usage - encourages conservation) or decreasing block (lower price for higher usage - encourages consumption, shown in L23 example).
    • Decreasing Block Example (Type 1 - Price changes only for units above cutoff):
      • Variables: Cutoff Quantity, High Price (HP) for units <= Cutoff, Low Price (LP) for units > Cutoff.
      • Total Price(D) = IF(D <= Cutoff, HP * D, HP * Cutoff + LP * (D - Cutoff))
      • Customer chooses consumption level D that maximizes Surplus = Cumulative Value(D) - Total Price(D). (Need to calculate Cumulative Value from inverse demand curve P=f(D)).
      • Profit = Revenue - (Units Bought * Unit Cost). Revenue is Total Price at chosen D.
    • Excel Solver Implementation:
      1. Setup columns: Demand levels (D), Value/WTP per unit (P=f(D)), Cumulative Value, Total Price (calculated using IF based on Cutoff, HP, LP), Surplus.
      2. Find Max Surplus, corresponding Units Bought (using INDEX/MATCH or VLOOKUP), Revenue (VLOOKUP on Total Price), Production Cost, Profit.
      3. Objective: Maximize Profit.
      4. Changing Variables: Cutoff, HP, LP cells.
      5. Constraints: Cutoff, HP, LP >= 0. HP >= LP. Optional: Integer constraints. Cutoff < Max Demand.
      6. Method: Evolutionary Solver is recommended due to IF statements causing non-smoothness.
    • Result: Finds optimal Cutoff, HP, LP yielding higher profit (e.g., ~$18) than single price (~$9).
  • 5.4 Detailed Explanation: Alternate Block Pricing (Lower Price for All, Excel Solver - L24)
    • Concept: Similar to block pricing, but if consumption exceeds the cutoff, the lower price applies to all units consumed.
    • Model Logic:
      • Total Price(D) = IF(D >= Cutoff, LP * D, HP * D)
    • Excel Solver Implementation: Same setup as L23, but use the different Total Price formula. Still use Evolutionary Solver.
    • Result: Also yields higher profit (~$18) than single price. The specific optimal Cutoff/HP/LP values might differ slightly from the other block pricing type, but the overall benefit over single pricing is similar.
  • 5.5 Detailed Explanation: Two-Part Tariff (Fixed + Variable, Excel Solver Example - L24)
    • Concept: Price structure with a fixed fee (e.g., access charge, membership fee) plus a per-unit charge for consumption. Common in utilities, clubs, phone plans.
    • Model Logic:
      • Variables: Fixed Fee (FF), Variable Rate (VR) per unit.
      • Total Price(D) = FF + VR * D
    • Excel Solver Implementation: Same setup as block pricing (calculate Surplus, Units Bought, Revenue, Cost, Profit), but use the two-part tariff formula for Total Price.
    • Objective: Maximize Profit.
    • Changing Variables: Fixed Fee (FF), Variable Rate (VR) cells.
    • Constraints: FF >= 0, VR >= 0. Optional: Integer constraints.
    • Method: Evolutionary Solver likely still preferred due to the Maximum Surplus logic.
    • Result: Also yields higher profit (~$18) than single price. Optimal solution might involve high FF and low VR (e.g., FF=16, VR=2 in example).
  • 5.6 Detailed Explanation: Price Discrimination/Segmentation (WTP, Demand Curve - L25)
    • Concept: Charging different prices to different customer segments for the same or similar product/service, based on their willingness to pay (WTP). Goal is to capture more consumer surplus.
    • Prerequisite: Ability to segment customers and prevent arbitrage (low-price buyers reselling to high-price segment).
    • Finding WTP: Use market research (e.g., conjoint analysis) on a sample.
    • Deriving Demand Curve: From WTP data, calculate demand at various price points: Demand(P) = Count of customers with WTP >= P. Use COUNTIF in Excel. Fit a trendline (linear or other) to get Demand = f(Price).
  • 5.7 Detailed Explanation: Single vs. Two-Price Optimization (Excel Solver - L25)
    • Single Price: Find optimal P to maximize Revenue = P * (Demand(P)). Use Solver.
      • Example Result: Optimal P=281.5, Max Revenue=79000.
    • Two Prices (High/Low):
      • Variables: High Price (P_H), Low Price (P_L), with P_H >= P_L.
      • Sell first to high-WTP segment at P_H, then to next segment at P_L.
      • Demand High (q_H) = Total Demand at P_H = f(P_H).
      • Demand Low (q_L) = (Total Demand at P_L) - (Demand High) = f(P_L) - q_H.
      • Total Revenue = (P_H * q_H) + (P_L * q_L).
      • Excel Solver: Maximize Total Revenue by changing P_H and P_L, subject to P_H >= P_L, P_H, P_L >= 0, and demands >= 0.
      • Example Result: Optimal P_H=413, P_L=263, Max Revenue=105000. Significantly higher than single price.
  • 5.8 Detailed Explanation: Price Discrimination with Capacity Constraint (L25)
    • Concept: Adds a limit on the total number of units that can be sold across all segments. Common in airlines, hotels, events.
    • Model Logic: Same as two-price optimization, but add constraint: Total Units Sold <= Capacity.
      • q_H + q_L <= Capacity
    • Excel Solver: Add the capacity constraint to the two-price optimization setup.
    • Result: Optimal prices adjust to meet the capacity limit. Maximum revenue will be less than or equal to the unconstrained case. (Example: Capacity=300 -> P_H=406.5, P_L=206.5, Max Revenue=101400).
  • 5.9 Detailed Explanation: Markdown Pricing (Concept, Excel Solver Example - L26)
    • Concept: Reducing prices over time (e.g., across seasons or sales periods) to sell off inventory or cater to different price sensitivities arriving at different times. Similar outcome to skimming (decreasing prices) but often driven by inventory or time-based sensitivity shifts.
    • Model:
      • Demand in period t = f_t(Price_t) (Demand function might change per period based on sensitivity/slope).
      • Total Revenue = Sum(Price_t * Demand_t).
    • Excel Solver Implementation:
      1. Setup: Time periods, Price (Variable), Demand (f_t(Price)), Revenue.
      2. Objective: Maximize Total Revenue.
      3. Changing Variables: Prices for all periods.
      4. Constraints:
        • Prices >= 0, Price <= Upper Bound.
        • Capacity/Inventory Constraint: Sum(Demand_t) = Total Units Available (if selling fixed inventory like swimsuits).
      • Example (Swimsuits, 400 units): Solver finds decreasing prices (213, 178, 154) that sell exactly 400 units and maximize revenue.
  • 5.10 Detailed Explanation: Dynamic Pricing (Concept, Excel Solver Example - L26)
    • Concept: Adjusting prices dynamically based on changing demand, costs, competitor prices, or price sensitivity over time. Similar setup to Markdown but without a fixed inventory constraint. Can include costs.
    • Model:
      • Demand(t) = f_t(Price(t))
      • Cost(t) = Unit Cost * Demand(t)
      • Profit(t) = (Price(t) - Unit Cost) * Demand(t)
      • Total Profit = Sum(Profit(t))
    • Excel Solver Implementation: Maximize Total Profit by changing Prices, subject to Price bounds. No total quantity constraint.
    • Result: Also results in decreasing prices over time if sensitivity increases (slope becomes steeper) or costs change. Example yields prices 166, 133, 111.
  • 5.11 Detailed Explanation: Mixed Bundling Optimization (Internet/TV/Cell Example - L27)
    • Concept: Offering both individual items and bundles, finding prices for all options to maximize total revenue. Customers choose the option giving the highest positive Consumer Surplus (WTP - Price).
    • Steps (Excel):
      1. Input WTP for individual items per customer.
      2. Calculate WTP for all possible bundles (assuming additive WTP).
      3. Set up cells for Prices of all individual items and bundles (Decision Variables).
      4. For each customer, calculate Consumer Surplus for all options (WTP - Price).
      5. Find the Maximum Surplus for each customer.
      6. Determine Chosen Option Index: IF(Max Surplus > 0, MATCH(Max Surplus, Surplus Range), 0).
      7. Calculate Revenue per Customer: IF(Chosen Index > 0, Price of Chosen Option, 0). Use HLOOKUP or INDEX based on the index to get the price.
      8. Calculate Total Revenue (Sum across customers).
    • Excel Solver:
      1. Objective: Maximize Total Revenue.
      2. Changing Variables: Cells with the prices for all 7 options.
      3. Constraints:
        • Prices >= 0, Prices <= Upper Bound.
        • Anti-Arbitrage: Bundle price <= Sum of component prices (e.g., P_All <= P_I + P_T + P_C, P_IT <= P_I + P_T).
        • Rationality: Bundle price >= Max price of any single component within it (e.g., P_IT >= MAX(P_I, P_T)). Crucial correction from L27.
      4. Method: Evolutionary Solver.
    • Result: Finds optimal prices for all 7 options simultaneously (e.g., Total Revenue 2343).
  • 5.12 Detailed Explanation: Sales Promotion Pricing Strategy (Simulation Example - L28)
    • Concept: Analyzing the effect of periodic price promotions on sales and revenue over time, considering customer dynamics (new arrivals, repurchase cycles).
    • Model:
      • Track customer segments (by WTP: High, Medium, Low) and their state (Buyer, Non-buyer) over time.
      • Define Price options (e.g., High=$80, Medium=$60, Low=$40) linked to Price Codes (1, 2, 3).
      • Sales in period t depend on Price(t) and the number of Buyers in each segment willing to pay that price.
      • Update Buyer/Non-buyer counts for period t+1 based on: Sales(t), repurchase probabilities (e.g., 30% buy again next year, 70% buy in 2 years), and new customer arrivals. Note: Specific formulas shown in L28 were complex and potentially needed refinement based on description.
      • Calculate Revenue(t) = Total Sales(t) * Price(t).
      • Calculate Total Revenue = Sum(Revenue(t)).
    • Excel Solver:
      1. Objective: Maximize Total Revenue.
      2. Changing Variables: Price Codes (1, 2, or 3) for each time period.
      3. Constraints: Price Codes are integers between 1 and 3.
      4. Method: Evolutionary Solver.
    • Result: Optimal strategy often involves alternating between a medium/high price and a low promotional price (e.g., 2, 1, 2, 1...) to capture different segments over time.

  • 6.6 Detailed Explanation: Adstock Concept (Decay, Lambda - L30)
    • Concept: Advertising effects persist over time but gradually diminish (decay/wear out). Current advertising impact depends on past advertising efforts stored as "stock".
    • Adstock Formula:
      Adstock(t) = lambda * Adstock(t-1) + Current_Ad_Spend(t)
      • lambda (λ): Decay rate or carry-over effect (0 <= λ < 1). Higher lambda means slower decay, effect lasts longer.
      • Adstock(t-1): Adstock value from the previous period.
      • Current_Ad_Spend(t): Expenditure in the current period.
    • Initial Stock: Need an initial value Adstock(0) for the first period calculation. This, along with lambda, is often estimated.
  • 6.7 Detailed Explanation: Combined Marketing Mix Model Equation (Multiplicative/Additive - L30, L31)
    • Goal: Model Sales as a function of multiple marketing mix elements simultaneously, including dynamic effects like Adstock.
    • Common Form (Mixed Multiplicative/Additive): Combines components known to have multiplicative effects (Price, Margin elasticities, Seasonality) with additive effects (Trend, Adstock impacts).
      Sales_t = Baseline * (Price_t ^ Elas_P) * (CompP_t ^ Elas_CP) * (Margin_t ^ Elas_M) * (CompM_t ^ Elas_CM) * SeasIdx_t
         + (Trend_Slope * t)
         + (Beta_D * AdstockD_t) + (Beta_P * AdstockP_t) + ... + (Beta_RND * AdstockRND_t)
         + (Beta_Int * InteractionTerm_t) + ...
         + Error_t
    • Requires estimating Baseline constant, Elasticities, Seasonal Indices, Trend slope, Betas for each Adstock, Interaction Betas.

    • Concept: Use Excel Solver to find parameters minimizing the error between actual sales and predicted sales from the MMM equation.

      3. Calculate Adstocks: Create columns for each Adstock type (Digital, TV, R&D...). Calculate period-by-period using the Adstock formula, referencing parameter cells (Lambda, Initial Stock) with absolute refs ($).
      4. Calculate Sales Forecast: Implement the full MMM equation in a new column, referencing data columns (Price, Quarter, etc.) and parameter cells ($) and calculated Adstock columns. Use VLOOKUP for Seasonal Index based on Quarter of Year. Use POWER for elasticities.
      5. Calculate Error: Calculate Absolute Percentage Error (ABS((Forecast - Actual) / Actual)) for each period. Calculate Mean Absolute Percentage Error (MAPE) (AVERAGE of APE column).
      6. Excel Solver:
        • Objective: Minimize MAPE cell.
        • Changing Variables: Select all parameter cells being estimated.
        • Constraints: Add bounds for parameters (e.g., Lambdas between 0-1, Initial Stocks >=0, Betas >=0, Elasticities signs based on theory, Seasonal Indices >=0).

    • Output: Optimized parameter values.

      Transformed_Spend = Max_Effect * (1 / (1 + exp(-alpha * Current_Ad_Spend)))
      • Requires estimating new parameters Max_Effect and alpha.
    • Modify Adstock calculation: Adstock(t) = lambda * Adstock(t-1) + Transformed_Spend(t). Optimize new parameters along with others.

    • Challenge: Estimating complex MMMs is difficult/slow in Excel Solver. R's optim() is more suitable.
    • Steps (R):
      1. Load Data: Read time series data. Create time variables (qtrn).
      2. Define Parameters: Set initial guess values for ALL parameters (Initial Stocks, Lambdas, Baseline A, Trend, Betas, Elasticities, Seasonality factors) in a single vector (starting). Define parameter order carefully.
      3. Define Bounds: Create vectors for lower and upper bounds for each parameter (lower, upper). Use -Inf/Inf for unbounded parameters (like elasticities).
      4. Create Error Function: Define an R function (e.g., sales_error_function) that:
        • Takes the parameter vector x as input.
        • Unpacks x into individual parameters based on the defined order.
        • Recalculates all Adstock series using the unpacked Lambdas and Initial Stocks.
        • Calculates predicted_sales using the full MMM equation with unpacked parameters and calculated Adstocks.
        • Calculates and returns the error metric (e.g., RMSE).
      5. Run Optimization: Use optim().
        • par = starting: Initial parameter guesses.
        • fn = sales_error_function: The function to minimize.
        • method = "L-BFGS-B": Method that allows bounds.
        • lower = lower, upper = upper: Parameter bounds.
      6. Interpret Results: optimization_result$par gives the optimized parameters. optimization_result$value gives the minimized error (RMSE). Check if parameters make theoretical sense (e.g., positive betas, correct elasticity signs, lambda < 1).
  • 6.13 Detailed Explanation: Media Planning Optimization (Impressions, Cost, Constraints, Solver - L33)
    • Goal: Allocate a TV advertising budget across different programs to maximize reach/impressions for target demographics, subject to cost constraints or minimum exposure goals.
    • Data: Program list, Cost per ad slot per program, Demographic audience profile per program (% watching per segment), Population size per segment, Exposure goals per segment.
    • Decision Variables: Number of Ads to place in each program.
    • Calculations (Excel):
      • Total Cost = SUMPRODUCT(Number of Ads, Cost per Ad).
      • Exposure per Segment = Population_Segment * SUMPRODUCT(Number of Ads, % Watching Segment).
    • Optimization Model 1 (Minimize Cost for Fixed Goals):
      1. Objective: Minimize Total Cost.
      2. Changing Variables: Number of Ads per program.
      3. Constraints: Ads are integers, Ads >= 0, Ads <= Max Limit (e.g., 20), Calculated Exposure per Segment >= Exposure Goal per Segment.
      4. Method: Evolutionary Solver.
    • Optimization Model 2 (Minimize Cost + Penalties):
      1. Calculate Deficit per Segment = IF(Exposure < Goal, Goal - Exposure, 0).
      2. Calculate Total Penalty = SUM(Deficits) * Penalty Rate.
      3. Calculate Non-linear Ad Cost (using HLOOKUP on cost table based on number of ads).
      4. Objective: Minimize (Total Non-linear Ad Cost + Total Penalty).
      5. Changing Variables: Number of Ads per program.
      6. Constraints: Ads are integers, Ads >= 0, Ads <= Max Limit (e.g., 10 from lookup table). No hard exposure constraint needed.

  • 7.5 Detailed Explanation: Collaborative Filtering (CF) Concept (User-Based vs Item-Based - L34, L35)
    • Concept: Leverages the "wisdom of the crowd." Assumes users who agreed in the past (liked/bought similar items) will agree in the future.
    • User-Based CF (UBCF):
      1. Find users similar to the target user based on past interactions (ratings/purchases).
      2. Recommend items liked by these similar users but not yet seen by the target user.
      • Analogy: Ask friends with similar movie tastes for recommendations.
    • Item-Based CF (IBCF):
      1. Find items similar to items the target user has liked/purchased in the past. Similarity is based on how often users interact with both items.
      2. Recommend these similar items.
      • Analogy: If you liked Star Wars Ep IV, you might like Ep V and VI because they are similar (often liked by the same people).
    • Comparison:
      • UBCF: Computationally expensive for many users. Similarity matrix is Users x Users.
      • IBCF: Often preferred for large systems as #Items < #Users typically. Similarity matrix (Items x Items) is smaller and more stable (item similarities change less often than user similarities). Offline calculation of item similarity is feasible.
  • 7.6 Detailed Explanation: Content-Based Filtering Concept (L34)
    • Concept: Recommends items based on the features of items the user liked previously.
    • Process:
      1. Extract item features (genre, keywords, specs).
      2. Build user profile based on features of liked items.
      3. Recommend items with features matching the user profile.
    • Pros: Handles new items (if features available), doesn't need other users' data, explains recommendations, handles unique tastes.
    • Cons: Requires structured content features, limited exploration (recommends similar items), ignores quality judgments from others.
  • 7.7 Detailed Explanation: Similarity Measures (Cosine, Correlation - L35)
    • Goal: Quantify how similar two users (rows) or two items (columns) are based on their interaction vectors in the user-item matrix.
    • Cosine Similarity: Measures the cosine of the angle between two vectors. Ignores magnitude, focuses on orientation. Value between -1 and 1 (often 0 to 1 for non-negative data). Higher value = more similar. Suitable for sparse data. Similarity = (A • B) / (||A|| * ||B||)
    • Pearson Correlation: Measures linear correlation between two vectors. Value between -1 and 1. Accounts for differences in rating scales (mean-centers). Often used when data is ratings.
    • Euclidean Distance: Measures straight-line distance. Lower value = more similar. Often needs standardization for different scales.
    • Choice depends on data type (ratings vs. binary) and desired properties.

  • 8.2 Detailed Explanation: RFM Analysis - Concept & Purpose (Behavioral Segmentation - L40)
    • Concept: A method to segment customers based on their past purchase behavior using three dimensions:
      • Recency (R): How recently did the customer make a purchase? (Time since last purchase). Lower time = Better.
      • Frequency (F): How often does the customer purchase? (Number of purchases in a period). Higher count = Better.
      • Monetary (M): How much does the customer spend? (Total value of purchases in a period). Higher value = Better.
    • Purpose: Identify high-value customers (high R, F, M), low-value customers, potentially churned customers (low R), and target marketing efforts (promotions, reactivation) accordingly. Simple, intuitive, widely used.
    • Limitations: Primarily backward-looking; not ideal for infrequent purchase categories.
  • 8.3 Detailed Explanation: RFM Metrics Defined (Recency, Frequency, Monetary - L40)
    • Recency: Calculated as Reference Date - Last Purchase Date. Reference date is often today (Sys.Date()) or the last date in the dataset. Measured in days, weeks, months. Lower value is better.
    • Frequency: Number of transactions or purchase occasions within a defined period (e.g., last year, last 2 years). Higher value is better.
    • Monetary: Total amount spent by the customer within a defined period. Higher value is better.
    • Data Needs: Customer ID, Transaction Date, Transaction Value. Need to aggregate transaction data to customer level first.
  • 8.4 Detailed Explanation: RFM Scoring Procedure (Sorting, Deciles/Manual Bins, Weights - L40)
    • Goal: Convert raw R, F, M values into scores (e.g., 0-9 or 1-10) for easier comparison and combination.
    • Method 1: Deciles (ntile):
      1. Calculate raw R, F, M per customer.
      2. For Frequency and Monetary: Sort customers by value (ascending). Divide into 10 equal groups (deciles). Assign score 0 to lowest decile, 1 to next, ..., 9 to highest decile. (Use ntile(value, 10) - 1).
      3. For Recency: Sort customers by time distance (ascending). Divide into 10 deciles. Assign score 9 to lowest distance decile (most recent), 8 to next, ..., 0 to highest distance decile (least recent). (Use 10 - ntile(time_distance, 10)).
    • Method 2: Manual Binning:
      1. Examine the distribution of raw R, F, M values (histograms).
      2. Define score bins manually based on the distribution and business logic, especially for skewed data (like Monetary). Assign scores (e.g., 0-9) to each bin. (Use case_when or nested ifelse).
    • Combining Scores: Create a single RFM score per customer.
      • Weighted Sum: Common method RFM Score = wR*R_score + wF*F_score + wM*M_score. Typical weights: 100*R + 10*F + 1*M. This prioritizes Recency heavily.
      • Concatenation: Simply paste scores together (e.g., R=9, F=7, M=9 -> "979"). Allows easy identification of R/F/M scores but harder to rank directly.
      • Regression Weights: Use coefficients from a regression model predicting profitability based on R, F, M scores as weights.
    • Ranking: Rank customers based on the combined RFM score (descending). Highest score = most valuable.

  • 8.9 Detailed Explanation: Association Rules (Antecedent -> Consequent) & Metrics (Support, Confidence, Lift - L42)
    • Rule Format: IF {Antecedent Itemset} THEN {Consequent Itemset}. Often simplified to {A, B} => {C}.
    • Metrics:
      • Support (Rule): Frequency of the entire itemset (Antecedent + Consequent) appearing together in transactions.
        Support(A->C) = P(A and C) = #(A and C) / Total Transactions. Measures how often the rule applies.
      • Confidence (Rule): Conditional probability of finding the Consequent given the Antecedent is present.
        Confidence(A->C) = P(C | A) = Support(A->C) / Support(A) = #(A and C) / #(A). Measures rule reliability/accuracy.
      • Lift (Rule): Ratio of confidence to the baseline probability of the Consequent. Measures how much more likely C is purchased when A is purchased, compared to C's overall purchase rate.
        Lift(A->C) = Confidence(A->C) / Support(C) = P(C | A) / P(C). Measures strength/interestingness of association.
        • Lift > 1: Positive association (buy together more than chance).
        • Lift = 1: Independence.
        • Lift < 1: Negative association (buy together less than chance). Higher lift = stronger rule.
  • 8.10 Detailed Explanation: Identifying Interesting Rules (Surprise - L42)
    • Concept: Rules are interesting if they reveal associations that are stronger than expected by chance (high Lift).
    • Example (Bread & Washing Powder): If P(Bread)=10%, P(Powder)=4%, expected co-occurrence P(Bread)*P(Powder) = 0.4%. If observed co-occurrence is 2% (5 times higher), the rule is surprising and potentially actionable (e.g., strategic store placement).
  • 8.11 Detailed Explanation: Apriori Algorithm Concept (Min Support, Large Itemsets, Pruning - L43)
    • Problem: Checking all possible rules is infeasible for large datasets.
    • Apriori Approach: Two stages:
      1. Find Frequent (Large) Itemsets: Identify itemsets appearing more often than a Minimum Support threshold.
      2. Generate Rules: Create rules only from these frequent itemsets, checking against a Minimum Confidence threshold.
    • Apriori Property: Any subset of a frequent itemset must also be frequent. Conversely, if an itemset contains an infrequent subset, it cannot be frequent.
    • Algorithm:
      1. Find frequent 1-itemsets (L1).
      2. Generate candidate 2-itemsets (C2) from L1. Prune C2 (subsets must be in L1 - trivial here). Scan data for support, find L2.
      3. Generate candidate 3-itemsets (C3) from L2 (joining pairs from L2 sharing first item). Prune C3: Remove candidates whose 2-item subsets are not all in L2. Scan data for support, find L3.
      4. Repeat until no more frequent k-itemsets are found.
    • Benefit: Pruning step drastically reduces the number of itemsets needing support calculation.

    • Context: Comparing CLV for Small vs. Large company customer segments.
    • Data Needed per Segment:
      • Initial Acquisition Cost per customer.
      • Annual Sales/Revenue per customer (can grow over time).
      • Annual Margin (%) per customer (can grow over time).
      • Annual Marketing/Retention Expense per customer (can decrease over time).
      • Annual Retention Rate (%) (probability customer stays for the next year).
      • Discount Rate.
      • Analysis Horizon (e.g., 10 years).
    • Calculation Steps (Spreadsheet):
      1. Calculate Annual Margin ($): Annual Sales * Annual Margin %.
      2. Calculate Annual Contribution: Margin ($) - Marketing Expense. For Year 0/1, subtract Acquisition Cost instead of Marketing Expense.
      3. Calculate Cumulative Retention Probability: Prob(Retained at Year t) = Prob(Retained at Year t-1) * Retention Rate(Year t-1). Starts at 1 for Year 0/1.
      4. Calculate Expected Contribution per Year: Annual Contribution * Prob(Retained at Year t). This weights the profit by the probability the customer is still active.
      5. Calculate Discount Factor: 1 / (1 + Discount Rate)^t (where t=0 for year 1, t=1 for year 2, etc.).
      6. Calculate Discounted Expected Contribution (NPV) per Year: Expected Contribution * Discount Factor.
      7. Total CLV per Customer: SUM(Discounted Expected Contribution over all years).
    • Results (Buford):
      • Small Co CLV: $2197
      • Large Co CLV: $4014
    • Interpretation: Large companies are more valuable per customer over their lifetime, despite high initial acquisition cost and first-year loss. Decision depends on total segment value (CLV * #Customers) and company's ability to fund initial losses.

    • Concept: Statistical methods for analyzing "time-to-event" data. In marketing, the event is often customer churn ("death").
    • Goal: Understand how long customers "survive" (remain active) and identify factors influencing survival time.
    • Survival Function S(t): Probability of surviving beyond time t. P(Lifetime > t). Typically decreases over time.
    • Expected Lifetime: Can be estimated from the survival function (area under the curve or weighted average). Used in CLV.
    • Hazard Rate h(t): Instantaneous risk of the event (churn) occurring at time t, given survival up to time t. Higher hazard rate = steeper drop in survival curve = shorter expected lifetime.
    • Applications: Predicting churn time, identifying high-risk periods/customers, comparing survival between groups (e.g., male vs female, different plans), evaluating impact of interventions on survival time.
  • 9.16 Detailed Explanation: Kaplan-Meier Estimator (Non-parametric - L50)
    • Concept: A non-parametric method to estimate the survival function S(t) directly from observed data (survival times and event status).
    • Calculation: Step-wise calculation. S(t_j) = S(t_{j-1}) * (1 - d_j / n_j). Where d_j = number of events at time t_j, n_j = number at risk just before t_j. Accounts for censored data (observations where the event didn't occur during the study period).
    • Output: Survival probabilities at different time points. Can be plotted as a Kaplan-Meier curve (step function).
    • Comparison: Can plot separate curves for different groups (e.g., treatment A vs B). Use Log-Rank Test to statistically test if the survival curves between groups are significantly different (p-value < 0.05 indicates significant difference).
  • 9.17 Detailed Explanation: Cox Proportional Hazard Model (Semi-parametric Regression - L50)
    • Concept: A regression model for survival data. Models the hazard rate as a function of covariates (predictor variables), without assuming a specific distribution for survival times (semi-parametric).
    • Model Equation: h(t | X) = h0(t) * exp(B1*X1 + B2*X2 + ...)
      • h0(t): Baseline hazard function (hazard when all X=0). Not estimated directly.
      • X: Covariates (e.g., age, gender, plan type).
      • B: Coefficients estimated from data.
    • Proportional Hazards Assumption: Assumes the ratio of hazards between any two individuals is constant over time. The effect of covariates is multiplicative on the baseline hazard.
    • Interpretation:
      • Focus on the Hazard Ratio (HR) = exp(Coefficient B).
      • HR > 1: Covariate increases the hazard (risk of churn). e.g., HR=1.5 means 50% higher risk.
      • HR < 1: Covariate decreases the hazard (risk of churn, protective). e.g., HR=0.7 means 30% lower risk.
      • HR = 1: Covariate has no effect on hazard.
      • Check coefficient significance (p-value < 0.05).
    • Advantage: Allows assessing the impact of multiple predictors simultaneously on survival/churn risk, controlling for other factors. Identifies drivers of survival time.

  • 10.5 Detailed Explanation: Bag-of-Tokens & DTM (Document Term Matrix - L51, L53)
    • Bag-of-Tokens/Words: Representing a document as an unordered collection (a "bag") of its words (tokens), disregarding grammar and word order but keeping multiplicity.
    • Document Term Matrix (DTM): A mathematical matrix representing term frequencies in documents.
      • Rows = Documents
      • Columns = Unique Terms (Tokens) across the entire corpus.
      • Cells (i, j) = Frequency of term j in document i.
    • Creation in R: Use tm::DocumentTermMatrix(cleaned_corpus).
    • Sparsity: DTMs are typically very sparse (mostly zeros) because most documents only contain a small subset of all possible terms. tm stores DTMs efficiently.
    • Analysis: DTM is the input for many text mining algorithms (TF-IDF, topic modeling, classification).
  • 10.6 Detailed Explanation: TF-IDF (Term Frequency-Inverse Document Frequency - L52)
    • Purpose: A numerical statistic reflecting how important a word is to a document within a collection (corpus). Weights terms based on frequency within document vs. frequency across documents.
    • Term Frequency (TF): How often a term appears in a specific document. Higher TF suggests importance to that document.
      TF(term, doc) = (Number of times term appears in doc) / (Total words in doc)
    • Inverse Document Frequency (IDF): Measures how common or rare a term is across all documents. Rare words get higher IDF scores.
      IDF(term) = log(Total number of documents / Number of documents containing term)
    • TF-IDF Score: Product of TF and IDF.
      TF-IDF(term, doc) = TF(term, doc) * IDF(term)
    • Interpretation: High TF-IDF score indicates a term is frequent in a specific document but relatively rare across the corpus, making it a good indicator of the document's specific topic/content. Words common across all documents (like "hotel" in hotel reviews) get low IDF and thus lower TF-IDF scores.

  • 10.9 Detailed Explanation: Naive Bayes Algorithm (Bayes Theorem, Spam Example - L54)
    • Concept: A probabilistic classifier based on Bayes' Theorem, with a "naive" assumption of independence between features (predictors). Commonly used for text classification.
    • Bayes Theorem: P(Class | Features) = [P(Features | Class) * P(Class)] / P(Features)
    • Naive Assumption: Assumes features (e.g., presence/absence of words) are conditionally independent given the class.
      P(Features | Class) = P(Feature1 | Class) * P(Feature2 | Class) * ...
    • Classification: Calculate the score (proportional to posterior probability) for each class: Score(Class) ∝ P(Class) * Π P(Feature_i | Class). Assign the document to the class with the highest score.
    • Example (Spam Detection with "Viagra"):
      • Calculate P(Spam | "Viagra") using P("Viagra" | Spam), P(Spam), P("Viagra") from training data frequencies.
      • Result P(Spam | "Viagra") = 0.8. If > cutoff (e.g., 0.5), classify as Spam.
    • Multiple Features: Multiply conditional probabilities P(Word | Class) for all words present/absent in the message, along with the prior P(Class). Normalize scores to get probabilities.
  • 10.10 Detailed Explanation: Naive Bayes Strengths/Weaknesses & Limitations (Zero Freq/Laplace, Continuous Data/Binning - L54)
    • Strengths: Simple, fast, effective for text, handles noise/missing data well, needs relatively few samples, scales well.
    • Weaknesses:
      • Independence Assumption: Often violated in reality (words are not independent), but often works well despite this.
      • Numeric Features: Not ideal; requires discretization (binning).
      • Probability Reliability: Predicted class is usually reliable, but exact probability estimates might be less accurate than other models.
    • Limitations & Solutions:
      • Zero Frequency Problem: If a word in a new message never appeared with a specific class in training, P(Word | Class) becomes 0, making the entire score 0.
      • Solution: Laplace/Add-one Smoothing: Add 1 (or small alpha) to all word counts when calculating conditional probabilities. P(Word | Class) = (Count(Word & Class) + 1) / (Count(Class) + VocabularySize). Prevents zero probabilities.
      • Continuous Data: Convert continuous features (e.g., email arrival time) into categorical bins before applying Naive Bayes.

5. Glossary of Key Terminology

(Alphabetical Order)
  • Adjacency Matrix: A square matrix representing connections in a network, where rows and columns correspond to nodes.
  • Adstock: The residual or carry-over effect of advertising expenditure over time, accounting for decay.
  • Afinn: A sentiment lexicon assigning words scores from -5 (negative) to +5 (positive).
  • Agglomerative Clustering: A hierarchical clustering method that starts with individual points and merges the closest clusters iteratively.
  • Apriori Algorithm: An efficient algorithm for mining frequent itemsets and association rules from transaction data.
  • Association Rule: A rule indicating the likelihood of items occurring together in transaction data (e.g., IF {A} THEN {B}).
  • Attribute (Conjoint): A feature or characteristic of a product/service (e.g., Brand, Price).
  • AUC (Area Under Curve): A metric summarizing the performance of a binary classifier based on the ROC curve (higher is better).
  • Bag-of-Tokens/Words: A representation of text that ignores grammar and word order, focusing only on word counts/presence.
  • Bass Diffusion Model: A mathematical model describing the adoption rate of new products over time, based on innovators and imitators.
  • Bayes Theorem: A theorem describing the probability of an event based on prior knowledge of conditions related to the event. P(A|B) = [P(B|A)P(A)] / P(B).
  • Behavioral Segmentation: Grouping customers based on their actions, usage, responses, or knowledge related to products/services.
  • Bing (Lexicon): A sentiment lexicon classifying words as either positive or negative.
  • Binning / Discretization: Converting continuous data into a finite number of intervals or categories.
  • Bundle Pricing: Selling two or more products/services together as a package, often at a special price.
  • Centrality: A measure of a node's importance or prominence within a social network (e.g., degree centrality).
  • Choice-Based Conjoint (CBC): A conjoint analysis method where respondents choose their preferred option from small sets of alternatives.
  • Churn (Customer Attrition): The event where a customer stops using a company's product or service.
  • Cluster Analysis: Techniques used to group similar data points together based on measured characteristics.
  • CLV (Customer Lifetime Value): The total predicted net profit attributed to the entire future relationship with a customer.
  • Coefficient of Imitation (q): Parameter in the Bass model representing adoption influenced by previous adopters (word-of-mouth).
  • Coefficient of Innovation (p): Parameter in the Bass model representing adoption by innovators, independent of others.
  • Cold Start Problem: Difficulty in making recommendations for new users (no history) or new items (no interactions).
  • Collaborative Filtering (CF): A recommendation technique based on the past behavior of similar users (user-based) or similarity between items (item-based).
  • Conditional Logit: A statistical model used to analyze choices made from a set of alternatives, often used for CBC data.
  • Conditional Probability: The probability of an event occurring given that another event has already occurred, P(A|B).
  • Confidence (Association Rule): A measure of rule reliability; the probability of the consequent occurring given the antecedent. P(C|A).
  • Conjoint Analysis: A market research technique to determine how people value different attributes (features, functions, benefits) that make up an individual product or service.
  • Consumer Surplus: The difference between a consumer's willingness to pay for a product and the actual price paid.
  • Content-Based Filtering: A recommendation technique based on the features of items and a user's profile of preferred features.
  • Corpus: A large collection of structured text documents used for statistical analysis and hypothesis testing in NLP.
  • Correlation: A statistical measure indicating the extent to which two variables fluctuate together.
  • Cosine Similarity: A measure of similarity between two non-zero vectors based on the cosine of the angle between them, often used for text or sparse data.
  • Cox Proportional Hazard Model: A regression model used in survival analysis to relate covariates to the hazard rate.
  • Cross-Price Elasticity: Measures the responsiveness of the quantity demanded for one good when the price of another good changes.
  • CRM (Customer Relationship Management): Practices, strategies, and technologies used by companies to manage and analyze customer interactions and data throughout the customer lifecycle.
  • CSV (Comma Separated Values): A common file format for storing tabular data.
  • Dashboard: A visual interface providing at-a-glance views of key performance indicators (KPIs) relevant to a particular objective or business process.
  • Data Frame (R): A primary data structure in R, a list of vectors of equal length, representing a table or spreadsheet.
  • Decile: One of ten equal groups into which a population can be divided according to the distribution of values of a particular variable.
  • Demand Function: A mathematical expression relating the quantity of a good demanded to factors like price, income, etc.
  • Demographic Segmentation: Grouping customers based on objective characteristics like age, gender, income, occupation, etc.
  • Dendrogram: A tree diagram used to illustrate the arrangement of clusters produced by hierarchical clustering.
  • Dependency Parsing: Analyzing the grammatical structure of a sentence to establish relationships between "head" words and words which modify those heads.
  • Discount Rate: The interest rate used in discounted cash flow (DCF) analysis to determine the present value of future cash flows.
  • DTM (Document Term Matrix): A matrix where rows represent documents, columns represent terms, and cells contain the frequency of terms in documents.
  • Dynamic Pricing: Adjusting prices for goods or services based on current market demands and conditions.
  • Elasticity: A measure of the responsiveness of one variable to a change in another (e.g., price elasticity of demand).
  • Elbow Method: A heuristic used in determining the optimal number of clusters in K-Means clustering by plotting WSS against K.
  • Emotion Mining: Using NLP to identify and extract subjective information related to specific emotions (joy, anger, sadness, etc.) from text data.
  • Evolutionary Solver: An optimization method in Excel Solver suitable for non-smooth, non-linear problems, often used with IF functions or integer constraints.
  • Factor (R): A data type in R used to represent categorical variables with predefined levels.
  • GRG Nonlinear: An optimization method in Excel Solver for smooth non-linear problems.
  • Hazard Rate: The instantaneous rate at which an event (e.g., churn, failure) occurs at time t, given survival up to time t.
  • Hazard Ratio (HR): The ratio of hazard rates corresponding to two levels of an exposure variable, typically calculated from a Cox model (exp(coefficient)).
  • Hierarchical Clustering: A clustering method that builds a hierarchy (tree) of clusters.
  • Histogram: A graphical representation of the distribution of numerical data.
  • IBCF (Item-Based Collaborative Filtering): Recommending items similar to those a user liked previously.
  • IDF (Inverse Document Frequency): A measure of how much information a word provides, i.e., whether it's common or rare across all documents.
  • igraph: An R package for network analysis and visualization.
  • IMC (Integrated Marketing Communication): Coordinating various promotional elements to deliver a consistent message.
  • Itemset: A collection of one or more items in market basket analysis.
  • K-Means Clustering: A partitioning clustering method that aims to partition n observations into k clusters in which each observation belongs to the cluster with the nearest mean.
  • Kaplan-Meier Estimator: A non-parametric statistic used to estimate the survival function from lifetime data.
  • Lambda (λ): The decay rate or carry-over factor (0-1) used in Adstock calculations.
  • Laplace Smoothing (Add-one): A technique to handle the zero-frequency problem in Naive Bayes by adding a small value (typically 1) to counts.
  • Level (Conjoint/Factor): A specific value that an attribute or factor variable can take.
  • Lexicon (Sentiment): A dictionary of words annotated with their sentiment polarity (positive/negative) or score.
  • Lift (Association Rule): A measure of how much more likely the consequent is, given the antecedent, compared to the consequent's baseline probability. P(C|A) / P(C).
  • Linear Regression: A statistical method modeling the relationship between a dependent variable and one or more independent variables using a linear equation.
  • Logistic Regression: A statistical method for analyzing a dataset in which there are one or more independent variables that determine a binary outcome.
  • Long Tail: The strategy of selling a large number of unique items with relatively small quantities sold of each – usually in addition to selling fewer popular items in large quantities.
  • MAPE (Mean Absolute Percentage Error): A measure of prediction accuracy of a forecasting method in statistics.
  • Market Basket Analysis (MBA): A data mining technique used to identify purchase patterns by analyzing items frequently bought together in transactions.
  • Marketing Mix (4Ps): Product, Price, Place, Promotion – the set of controllable tactical marketing tools that a firm blends to produce the response it wants in the target market.
  • Marketing Mix Model (MMM): A statistical analysis used by marketers to estimate the impact of various marketing tactics on sales and forecast the impact of future tactics.
  • Mixed Bundling: Offering consumers the choice of buying products individually or as a bundle.
  • Multicollinearity: A statistical phenomenon in which two or more predictor variables in a multiple regression model are highly correlated. Checked using VIF.
  • Multinomial Logistic Regression: A classification method for problems with more than two discrete outcomes.
  • Naive Bayes Classifier: A probabilistic classifier based on applying Bayes' theorem with strong (naive) independence assumptions between features.
  • Net Present Value (NPV): The difference between the present value of cash inflows and the present value of cash outflows over a period of time.
  • NLP (Natural Language Processing): A field of computer science and linguistics concerned with the interactions between computers and human languages.
  • Node (Actor): An entity (e.g., person, organization) in a social network.
  • NRC (Emolex): A sentiment lexicon providing positive/negative classification and association with 8 basic emotions.
  • Optimization: The process of finding the best solution from a set of alternatives, often by maximizing or minimizing an objective function subject to constraints.
  • Orthogonal Design: An experimental design where the effects of different factors can be estimated independently of each other. Used in Conjoint Analysis.
  • Part-Worth Utility: The subjective value or preference a consumer attaches to a specific level of an attribute in Conjoint Analysis.
  • Path (Tie, Edge): A connection or relationship between nodes in a social network.
  • Pivot Chart (Excel): A graphical representation of the data summarized in a PivotTable.
  • Pivot Table (Excel): A data summarization tool used to draw statistics from a larger dataset.
  • Polarity (Sentiment): The degree of positivity or negativity expressed in text.
  • Positioning: Designing an offering and image to occupy a distinct place in the target market's mind.
  • Power Block Pricing: A pricing strategy where the price per unit changes based on the quantity consumed (tiered pricing).
  • Price Discrimination: Charging different prices to different customers for the same or similar product/service based on willingness to pay.
  • Price Elasticity of Demand: A measure of the sensitivity of quantity demanded to changes in price.
  • Psychographic Segmentation: Grouping customers based on lifestyle, personality, values, attitudes, or interests.
  • Pure Bundling: Offering products only as a bundle, not individually.
  • Random Forest: An ensemble learning method that operates by constructing multiple decision trees during training and outputting the class that is the mode of the classes (classification) or mean prediction (regression) of the individual trees.
  • recommenderlab: An R package providing infrastructure for building and evaluating recommendation algorithms.
  • Recency (RFM): Time elapsed since a customer's last purchase or activity.
  • Recommendation Engine: A system that predicts user preferences and suggests items they are likely to be interested in.
  • Regression Analysis: Statistical methods for estimating the relationships between a dependent variable and one or more independent variables.
  • Retention Rate: The percentage of customers who continue their relationship with a company over a specific period.
  • RFM Analysis: A marketing technique analyzing customer value based on Recency, Frequency, and Monetary value.
  • RMSE (Root Mean Squared Error): A measure of the differences between values predicted by a model and the values observed.
  • ROC Curve (Receiver Operating Characteristic): A graphical plot illustrating the diagnostic ability of a binary classifier system as its discrimination threshold is varied. Plots True Positive Rate vs. False Positive Rate.
  • S-curve: A curve shape often depicting the growth of a variable (like cumulative adoption) over time, characterized by slow initial growth, rapid acceleration, and then saturation.
  • Scanner Data: Detailed data on purchases collected by scanning barcodes at retail points of sale.
  • Seasonality: Patterns in time series data that repeat over fixed periods (e.g., yearly, quarterly).
  • Segmentation: The process of dividing a broad consumer or business market into sub-groups of consumers (segments) based on shared characteristics.
  • Sentiment Analysis (Opinion Mining): Using NLP and text analysis to identify and extract subjective information (positive, negative, neutral tone) from source materials.
  • Skimming Pricing: A pricing strategy starting with a high price and lowering it over time.
  • Slicer (Excel): An interactive control that allows users to filter data in PivotTables and PivotCharts easily.
  • SNA (Social Network Analysis): The mapping and measuring of relationships and flows between people, groups, organizations, or other connected information/knowledge entities.
  • Solver (Excel): An add-in tool for optimization and equation solving.
  • Sparsity: A property of matrices (like DTM or User-Item matrix) where most entries are zero.
  • Steady State: A long-term equilibrium condition in a dynamic system (like market share with constant brand switching) where variables no longer change over time.
  • Stemming: Reducing inflected (or sometimes derived) words to their word stem, base or root form.
  • Stopwords: Common words (like "the", "is", "in") filtered out during text pre-processing.
  • STP: Segmentation, Targeting, Positioning framework.
  • Structural Hole: A gap in a social network between two individuals or groups who do not have direct ties.
  • Support (Association Rule): The frequency or proportion of transactions containing a specific itemset. P(A and C).
  • Survival Analysis: Statistical methods for analyzing the expected duration until an event of interest occurs (e.g., churn, death, failure).
  • Survival Function S(t): The probability that an individual survives longer than time t.
  • Targeting: Selecting specific market segments to serve.
  • TF-IDF: Term Frequency–Inverse Document Frequency; a numerical statistic intended to reflect how important a word is to a document in a collection or corpus.
  • tidytext: An R package for text mining using tidy data principles.
  • Time Series: A sequence of data points indexed in time order.
  • tm Package (R): A major framework for text mining applications in R.
  • Tokenization: The process of breaking down text into smaller units called tokens (usually words).
  • Transaction Data: Data recording individual purchase events, typically listing items bought together.
  • Transition Matrix: A matrix describing the probabilities of moving from one state to another in a dynamic system (e.g., brand switching).
  • Trend: The general long-term direction of movement in a time series.
  • Two-Part Tariff: A pricing structure with a fixed fee plus a per-unit charge.
  • UBCF (User-Based Collaborative Filtering): Recommending items based on the preferences of similar users.
  • Unstructured Data: Data that does not have a pre-defined data model or is not organized in a pre-defined manner (e.g., text, images).
  • VIF (Variance Inflation Factor): A measure of multicollinearity among predictor variables in a regression model.
  • Word Cloud: A visual representation of text data where the size of each word indicates its frequency or importance.
  • Working Directory: The default file system location R uses for reading and writing files.
  • WSS (Within-Cluster Sum of Squares): A measure of the compactness of clusters in clustering analysis.
  • WTP (Willingness To Pay): The maximum price a customer is prepared to pay for a product or service.
